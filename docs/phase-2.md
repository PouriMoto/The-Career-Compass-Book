# فاز PWA و انتقال Studio — 2026-09-12

## خروجی

- manifest فارسی و RTL، scope ریشه و حالت standalone.
- آیکون‌های PNG 192 و 512 و maskable از SVG اختصاصی تولیدشده با کد؛ هیچ تصویر ورودی استفاده نشده است.
- تولید worker بعد از build، نام cache بر اساس BUILD_ID و فهرست منابع.
- نصب اتمیک shell و منابع JS/CSS؛ شکست دانلود یک منبع باعث شکست install می‌شود.
- در بازشدن مسیر ریشه، shell همان نسخه از cache استفاده می‌شود. API و پاسخ کاربران cache نمی‌شوند.
- worker تازه تا بسته‌شدن تب‌های قبلی منتظر می‌ماند. cleanup فقط cache با prefix همین اپ را پاک می‌کند و هیچ IndexedDB را تغییر نمی‌دهد.
- دکمه نصب در مرورگر پشتیبان و راهنمای نصب دستی؛ وضعیت آمادگی آفلاین جدا از وضعیت ذخیره داده نمایش داده می‌شود.

## اجرای بررسی

`npm run build` سپس `npm run test:e2e`؛ حالت dev عمداً worker ثبت نمی‌کند. تست cold-open یک تب را می‌بندد و در همان پروفایل یک تب جدید بدون شبکه باز می‌کند و پاسخ ذخیره‌شده را بررسی می‌کند. این تست جای تست نصب واقعی Android/iOS و restart کامل سیستم عامل نیست.

## استفاده مجدد

الگوی PWA فعلاً نمونه مخصوص یک shell Next در مسیر ریشه است. برای محصول دیگر cache prefix، manifest، scope و متن‌ها تغییر کنند. مسیرهای اضافی، auth، داده سرور و RSC routing نیازمند سیاست cache جدا هستند. source اصلی موتورهای عمومی همچنان `packages/studio-kit` است.

Studio مقصد صحیح: `../ai-studio-for-making-digital-product`؛ خروجی فاز در `releases/career-compass-0.2.0` ثبت می‌شود و Remember حفظ می‌شود. شماره 0.2.0 نسخه snapshot محصول است؛ API بسته موتور هنوز 0.1.0 است.
